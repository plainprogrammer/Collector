# Prices

Where market prices live, how their database is built and what may never cross from it to the rest of the instance. This is the current truth; when it and an older spec disagree, this doc is right.

## Scope

The prices database: its configuration, its tables, the connection class later models inherit, and the rules that keep prices global and apart from collectors' data (spec 081). The price source contract, with Scryfall's source and the rows of sources and series that a source's declaration writes (spec 085, #364). The daily refresh: its job, run record, guards and the three models it writes (spec 089, #365). The run's measurements (#366), the admin log (#367), the history levels (#368), the display (#369) and the operator's cost documentation (#370) will extend this doc.

Neighbouring areas: the backup that holds the prices database, its format and its restore are in [release and deploy](release-and-deploy.md). The printings that prices name are the catalog's ([catalog core](catalog-core.md)). The export format holds no price ([data portability](data-portability.md)).

## Glossary

- **Prices database:** the instance's fifth SQLite file, `storage/<environment>_prices.sqlite3`, with its migrations in `db/prices_migrate/` and its schema in `db/prices_structure.sql` (spec 081 decision 1; [ADR 0029](../adr/0029-prices-database-held-by-the-backup.md)).
- **Printing:** one catalog entry, named in the prices tables by `catalog_entry_id`, the id of its `catalog_entries` row (spec 081 decision 4).
- **Price source:** where prices come from, with the attribution a page shows and whether a hosted, paid instance may show it (`price_sources`; spec 081 decision 2).
- **Price series:** what a price means: a finish, an ISO 4217 currency and a kind such as `market`. Series are global, not per source (`price_series`; spec 081 decision 2).
- **Current price:** the latest known price of one printing in one series from one source (`current_prices`).
- **Price change:** one row of history, recorded on the day a price differs from the last one recorded; a row with no cents records that the price went away that day (`price_changes`; design decision 7).
- **Price refresh run:** one run of the daily refresh (`price_refresh_runs`, `PriceRefreshRun`): its identity, times, status and the counts of what it did to rows; #366 adds the measurements (spec 081 decision 2; spec 089 decision 2).
- **Applied:** a run that finished. A file is applied once: a finished run of the same source has the same `source_version` and `languages` (spec 089 decision 5).
- **Candidate:** a current price the file may speak for: its printing is a catalog entry of the type in a language the run read (retired or not) and its series is one the source declares today. An **absent** candidate has no quote in the file; a **withheld** removal is an absent candidate the run did not remove because the file could not be trusted (spec 089 decision 4).
- **Repriced:** a quote whose price differs from the current price. The run's count is `repriced`, not `changed`: Active Record reserves that attribute name (spec 089 v0.4.3).
- **Quote:** one price of one printing in one series from one source on one reported day, as a source yields it (`Prices::Sources::Quote`: the source's id for the printing, finish, currency, kind, whole cents and the day). Not a row: nothing stores a quote until #365 (spec 085 decision 2).
- **Reported on:** the day a source's data is from, not the day it was read. For Scryfall it is the UTC date in the bulk file's name (spec 085 decisions 2 and 4).
- **Three things named alike:** `PriceSource` is the model, a row of `price_sources`; `Prices::Sources` is the contract a source class implements; `Prices.sources` is the registry of source classes by key (spec 085 decisions 1, 7 and 11).

## Invariants

- **Prices live in their own file.** No price table is in the primary database, and the daily writes never touch it (spec 081 decision 1, FR-1; the design's anti-goal).
- **Prices are global.** No price table has `account_id` or `user_id`, and nothing of the prices database is in an export, a preview or an apply (spec 081 decision 4, AC-3.1, AC-3.2).
- **Nothing crosses the two files.** There is no foreign key from a price table to the primary (SQLite can't make one across files), and no query joins or attaches the two. Code looks up prices by printing. The test environment has both databases, so a join fails in the suite as it would in production (spec 081 decisions 1 and 4, AC-3.3, AC-3.4).
- **A price row may name a printing the primary doesn't have** (a backup's two snapshots are taken seconds apart; a retired entry). That is never an error: a reader finds no entry and shows nothing (spec 081 decision 4).
- **Foreign keys stay inside the prices file**, and each one is `on_delete: :restrict`: a source or a series that prices name can't be deleted (spec 081 decision 2, AC-3.3).
- **`current_prices` and `price_changes` are `WITHOUT ROWID`**: their primary key is the table, so the key is stored once. That holds on a database loaded from `db/prices_structure.sql` (a new instance, the test database) and on one built by the migrations (an upgraded instance), and `spec/prices_schema_spec.rb` fails when either table lacks the option (spec 081 decision 3, ruled 2026-11-13; AC-2.1 to AC-2.3).
- **The two large tables have no index beyond their primary key.** Lookups go by printing, the key's first column. An index on `price_source_id` or `price_series_id` would store most of the key again and undo the saving, so this is an accepted exception to "index every foreign key" (`.claude/rules/sqlite-and-migrations.md`). Deleting a source or a series would scan the table, and nothing does (spec 081 decision 2; the maintainer's ruling of 2026-11-13).
- **The prices schema names no collectible**: its migrations, its structure file and `PricesRecord` never name a game or a source (spec 081 decision 9, AC-3.5; `spec/prices_core_spec.rb`).
- **The backup holds the prices database** beside the primary; how is in [release and deploy](release-and-deploy.md) (spec 081 decision 6).
- **The contract's comment is the contract.** `Prices::Sources` (`app/models/prices/sources.rb`) is the one place what a source provides and what each part returns or raises is written; this doc points to it and does not restate it. There is no ADR for it (spec 085 decisions 1 and 12; Gate A, 2026-11-13). Core files (`app/models/prices.rb`, `app/models/prices/**`, `PriceSource`, `PriceSeries`) name no collectible, source or marketplace, comments included, and `spec/price_source_core_spec.rb` fails on one (spec 085 decisions 1 and 12, AC-4.1).
- **A source yields only the prices its file carries.** A price the file leaves empty has no quote. A `Malformed` that names a series is not an absence (the price exists and was not understood); one with a key and no series means no series of that printing may be read as absent; one with no key makes the run's absences untrustworthy. The reason: a refresh that deletes a price when its quote is absent must never delete one the source failed to parse, because the deletion is recorded in history that can't be fetched again. What the refresh does with each is the "Gone is not bad" invariant below (spec 085 decision 2; spec 089 decision 4).
- **`each_quote` makes no network call, writes nothing and reads no database.** It reads the local file its caller gives and streams it one line at a time. The contract has no members that fetch the file: acquiring it is #365's (spec 085 decision 3).
- **The date reported is the UTC date in the file's name.** A name with no date, or digits that are not a date, is an `IntegrityError` from `#reported_on` and from `#each_quote` before any quote is yielded, because a guessed date would put a wrong day into history that can't be fetched again (spec 085 decision 4, AC-2.4).
- **A price becomes cents from its digits, never through a float.** Anything that isn't one to nine digits with at most two decimals is a `Malformed` that names its series; `"0.00"` is a quote of 0 cents, and whether to show it is the display's (#369) (spec 085 decision 6, AC-2.6).
- **Quotes store what the file carries, twins included.** The EUR a non-English printing copies from its English twin is yielded as a quote of that printing; choosing the twin's price is a display rule that #369 owns (ruling 41, [research 083](../specs/083-non-english-printing-prices/research.md); spec 085 decision 5, AC-2.8).
- **Source and series rows are written by `PriceSource.sync!` and `PriceSeries.ensure!`** from a source's declaration, never seeded by a migration and never deleted. A corrected attribution takes effect at the next sync; a series a source stops declaring keeps its row; series are global, so sources that quote the same finish, currency and kind share one row. Both calls are idempotent and create through the unique indexes, so the caller that loses a race reads the winner's row (spec 085 decision 7, AC-3.1 to AC-3.6).
- **Every price table has a model**, all inheriting `PricesRecord`: `PriceSource`, `PriceSeries`, and, with the daily refresh, `CurrentPrice` and `PriceChange` (composite primary keys, bulk writes by key: `upsert_all(rows, unique_by: Model.primary_key)` and `delete_all`, which skip validations on purpose because each row comes from a validated `Quote`) and `PriceRefreshRun` (spec 085 decision 8; spec 089 decisions 2, 6 and 8).
- **The daily refresh reads the catalog source's file and nothing else.** `Prices::Refresh` asks `Catalog.source_for(type)` for `#languages`, `#current_version` and `#download`, so the catalog refresh and the price refresh read one file in `storage/catalog/<type>/`; a file one has downloaded the other reuses when both see the same version. `Prices::Sources` has no member for fetching. The run's `source_version` is the string the catalog keeps as its version. It is not a `Catalog::Operation`: it has its own job (`Prices::RefreshJob`, queue `sync`), its own run record and its own guard, because the catalog refresh must not learn of prices and the page for prices is #367's (spec 089 decision 1; roadmap ruling of 2026-11-13).
- **The source is looked up and synced before a run exists.** `Prices.source_class`, then `PriceSource.sync!`, then `PriceRefreshRun.start!`, because a run's source row is required (`price_source_id` is `NOT NULL`). An unregistered key or a source that fails verification fails the job with no run row: a defect of the build, not of a day (spec 089 decision 5, step 0).
- **One run at a time; a run left behind is closed.** `Prices::RefreshJob` holds a queue lock per source key (`LOCK_FOR`). `PriceRefreshRun.start!` closes each running run with no progress for `STALL_AFTER`, or carrying the starting job's own id, as `failed` with `interrupted`, then records the new run `skipped` (`already running`) if another still runs. Progress is a touch of the run row at every batch read (even one that writes nothing), every removal slice, and, while downloading, at most every `HEARTBEAT_EVERY` through the catalog source's optional `#progress=` hook (spec 089 decision 7).
- **A file is applied once, and the date is the file's.** The order: the source synced; the run opened; the catalog has no printing of the type (skipped, no date); the catalog source's current version and languages, and a finished run of the same source, version and languages (skipped `<version> already applied`, with that run's `run_on`); the download; the file's UTC date (`#reported_on`), written to the run; a file older than the latest `run_on` of the source's finished or failed runs (a failed run may have written rows) is skipped after the download, and a file of the same day with another version or language set is applied. `run_on` is nil until the date is known (spec 089 decisions 3 and 5; supersedes spec 081's `NOT NULL`).
- **Unchanged writes nothing; freshness is the latest finished run.** A quote equal to the current price writes no row, so `current_prices.reported_on` and `changed_on` are both the run date of the last write. A price is current as of the source's latest finished run's `run_on`, which a page labels "as of" (#369). Prices the run leaves alone (a language not read, a printing the primary lacks, a series no longer declared) go stale with no marker on their row. While the ceiling below fails every run, no run finishes and the label lags (spec 089 decision 3).
- **The four cases of a quote.** Per printing and series, in one short transaction per batch of `BATCH_SIZE` printings: a printing the catalog lacks is skipped and counted once (`unknown_printings`; its quotes are in no other count); a price equal to the current one writes nothing (`unchanged`); a different one updates the current price and writes a history row for the run's date (`repriced`); one with no current price inserts both (`added`); the first quote of a printing and series in a file is judged and a repeat is ignored. History rows are upserted on their key, so a second file of one day replaces that day's row and a rerun can't duplicate. `quotes_seen = unchanged + repriced + added`. A quote of a series the source didn't declare raises `Prices::Sources::ConfigurationError` before its batch is written; earlier batches stand (spec 089 decision 6).
- **Gone is not bad.** A price is removed (the current price deleted, a history row with no cents for the run's date) only if its printing is a catalog entry in a language the run read, its series is declared, the file has no quote for it, and the file can be trusted: it was read to the end (a `Zlib::Error` fails the run and removes nothing; earlier batches stand), the source yielded at least one `Quote` (else `no valid quotes`, nothing written), no `Malformed` names no printing (a keyless one withholds every removal), none names the printing (withholds all its series) or its series (withholds that one), and the absent prices are at most `MAX_REMOVED_SHARE` of all candidate rows (compared exactly, after a first walk that counts them all; a breach withholds every removal and fails the run, saying how many of how many). An unreadable price is not an absent one. A removal batch deletes the current prices and upserts their blank history rows in one transaction, so a failure leaves both or neither. `removals_withheld` counts every absent candidate not removed. Failing items 1, 2 and the ceiling fail the run; the others finish it, because the next day's file removes the price if it is really gone (spec 089 decision 4; spec 085 decision 2).
- **No transaction holds the network or the primary.** The download, the file read and the lookup of entry ids on the primary (by `external_key`, per batch; no join across the files) happen outside any transaction on the prices database; the run row's progress write is outside the batch transaction; counts are tallied after a batch commits and persisted with each progress touch, so an `interrupted` run keeps its last counts. Pending printings and unreadable records both count toward `BATCH_SIZE` (spec 089 decisions 2 and 7; an automated security review).
- **Errors and their fates, with no discard.** Transient errors (`Catalog::Sources::TransientError`, `ActiveRecord::StatementTimeout`) and the download's size error (`Catalog::Sources::IntegrityError`) are retried (`polynomially_longer`, 3 attempts); a rate limit is rescheduled by `Catalog::RateLimitRetry`, included after `retry_on`; everything else (`Prices::Sources::IntegrityError`, a bad language setting, `Zlib::Error`, `Prices::Refresh::GuardError`, any other error) fails the job, with the run `failed` and its error. Nothing is `discard_on`: a failed job shows under Failed on `/admin/jobs`, a deliberate departure from `background-jobs.md`'s advice, because #367 doesn't exist yet and a discarded job would hide a guard that fired (spec 089 decision 7).
- **`hosted_paid_allowed?` is stated and stored, and nothing refuses a source by it yet.** No setting for the kind of instance exists; hosted mode (#392) adds one. Scryfall's is `true`, ruled by the maintainer on 2026-11-13 (roadmap rulings 27, 37 and 38). Issue #362 is open and its answer may change the value; the value is written only in `MTG::Scryfall::PriceQuotes.hosted_paid_allowed?` and in its spec (spec 085 decision 9).

## States and transitions

- **The prices database comes into being with the instance's start.** `bin/rails db:prepare` creates it on a new volume, loading `db/prices_structure.sql`, and on an upgraded one that lacks it. A missing `sqlite3` command at that point leaves the load undone and two `command not found` lines in the log, and `db:prepare` then runs every prices migration from scratch, which builds the same tables (spec 081 decision 3).
- **A run's status** is one of `running`, `finished`, `skipped` and `failed`, fixed by a check. A run opens `running` (`PriceRefreshRun.start!`) or, when another works, `skipped` with `already running`; it ends `finished` with its counts, `skipped` with its reason in `error` (no printing yet, already applied, an older file), or `failed` with `"<class>: <message>"` and the counts so far, and the error re-raised for the job's rules. A skipped run is never "applied" (spec 089 decisions 2, 5 and 7).

### What an operator sees when the job fails every day

There is no prices page until #367, so a daily failure shows in three places and has one standing cause worth knowing (spec 089 decision 7, Gate A, 2026-11-13):

- **One Failed job a day** under `/admin/jobs` (`Prices::RefreshJob`, queue `sync`), whose exception says what happened: `Prices::Refresh::GuardError` with how many of how many prices the file lacked, or `no valid quotes`; `Zlib::Error` for a cut-short or corrupt file; `Catalog::Sources::ConfigurationError` naming an unsupported `COLLECTOR_MTG_LANGUAGES` code. Solid Queue's hourly clearing removes only finished jobs, so an admin discards a failed job by hand.
- **A failed run row** in `price_refresh_runs` (read with `bin/rails runner`) with the same text in `error` and the counts so far; changes written before the failure stand, and nothing was removed.
- **A standing ceiling breach.** A real, lasting drop above `MAX_REMOVED_SHARE` of the market's prices is refused every day until that constant moves; it is a first guess until #366's run records measure the daily share of prices that disappear. A truncated or damaged file fixes itself with the next day's file. The "as of" label lags while no run finishes.

## Decisions not in an ADR

- **A change to `current_prices` or `price_changes` is a new migration that recreates the table.** On SQLite, Rails changes a column (`change_column`, `remove_column`, `rename_column`, `change_column_null`, `add_check_constraint` and the like) by copying the table into a new one built without its options, so `WITHOUT ROWID` would be silently lost. Write a migration that creates the new table with `options: "WITHOUT ROWID"`, copies the rows and swaps the names; `spec/prices_schema_spec.rb` fails otherwise. `add_column` of a nullable column is safe: SQLite's `ALTER TABLE ADD COLUMN` keeps the table. The first prices migration says the same in its header (spec 081 decision 3, AC-7.3).
- **`PricesRecord` has the writing role only**: nothing reads a replica, and a reading pool that the suite's restored-instance helper doesn't re-point would be a trap (spec 081 decision 5; plan review).
- **The structure file carries query-log comments.** Statements run in development end with `/*application='Collector'*/` (`config.active_record.query_log_tags_enabled`), SQLite stores them with the definition, and the dump keeps them. Production stores none. `spec/prices_schema_spec.rb` strips comments before it compares definitions (spec 081 execution, batch A).
- **The structure file needs the `sqlite3` command** where it is dumped (development, after a migration) and loaded (the test database, a new instance). It is in the image's runtime stage and on CI's runners; CI installs none itself (spec 081 decision 3).
- **The count is `repriced`, in a second migration.** Spec 089's first migration (`20261113190001`) added the count as `changed`; Active Record forbids that attribute name (`DangerousAttributeError`), found when the model was built. The unreleased migration stayed as built and `20261113190002` renames the column, so a database that applied either is right. The same two migrations make `run_on` nullable (a rebuild of the rowid table `price_refresh_runs`, which keeps its status check, foreign key and index) and add `job_id`, `languages` and the counts (spec 089 decision 2, v0.4.3).
- **Accepted limits of the refresh.** The `@seen` set of judged `[printing, series]` pairs (about 30 MB for 300,000 quotes), the unknown printings' keys and the held printings are held in memory for the run, bounded by the file; a removal slice sends one `DELETE` per printing; `quote.series` builds a validated `Series` per quote; `progress!` and `finish!` don't check the run is still `running` (a process resuming after the 6-hour lock lapsed could overwrite an `interrupted` closing). The measured first run is 18.4 s and a typical day 7.4 s for 110,000 cards and 275,000 quotes (spec 089 AC-5.6, the development machine, no threshold); #366's run records can reopen any of these (spec 089 implementation review).
- **A series the source no longer declares is left alone**, as a language not read is: a later build that drops one would otherwise fail every run on the ceiling or blank prices the file was never asked about (spec 089 v0.5.0; implementation review).
- **No ADR for the refresh.** The decisions are spec 089's, and this doc carries the rules (spec 089; Gate A, 2026-11-13).
- **The attribution wording and the hosted flag are the source's declaration**, code that ships with the build and takes effect at the next sync, not a migration's seed: a migration is never edited once released, and the text is a statement the project may need to correct (spec 085 decisions 7, 9 and 10).
- **No ADR for the contract.** The decisions are spec 085's, and the contract's comment and this doc carry the rules (spec 085 decision 12; Gate A, 2026-11-13).
- **Reading cost.** `each_quote` read a generated file of 50,000 cards (300,000 quotes) in 1.2 s on the development machine; the figure is a measurement with no threshold, for #365 and #366 to plan from (spec 085 execution, T2.3).
