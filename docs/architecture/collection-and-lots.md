# Collection and lots

What a collector owns and where it is kept: lots and their identity, the ways copies are added, edited, moved and removed, the collection's grid and table, bulk mode, number entry, and locations. This is the current truth; the specs it distils record what each feature promised when it shipped (see Sources and the [specs index](../specs/README.md)). How each page looks is the [design system](../design-system/README.md)'s; this doc names the patterns and does not restate them.

## Scope

**Covers:**

- The lot: `Lot`, its identity and key, merging and the 9,999 cap, and a lot's place (spec 004 FR-6; spec 032 decisions 1, 2; ADRs 0019, 0025).
- Adding, editing and removing one lot: quick add (`Catalog::QuickAddsController`), "Add a copy", "Edit copy" and "Remove" (`LotsController`, `Lots::RemovalsController`, `Lot::Form`) (spec 004 Stories 7, 9, 10; spec 032 Stories 1, 2; spec 065 Story 1).
- Moving copies: `Lot::Move`, `Lots::MovesController` (spec 032 Story 3, decision 4; spec 065 Story 2).
- What a picker lists and what a write may name: `Location::Choices`, `LocationChoicesHelper#location_options` and `Location.placeable` / `Location.find_placeable!`, for the lot form's Location, Move copies' To, bulk Move to…'s To, number entry's Location, the scanner sitting's Location and the collection filter's select (spec 065 decisions 1–4, FR-1; ADR 0028).
- What the card page and search say about the collector's copies: owned quantities on tiles, the "Not owned" marker, the card page's stats, "Your copies" and the owned counts of "Printings", and the `from=collection` mark (`Catalog::CardOverview`, `CardContext`) (spec 004 AC-6.3, AC-6.6, AC-8.4–AC-8.7, AC-8.9; spec 021; spec 032 Story 4).
- The collection page: the grid and the table, the name and location filters, the counts, the saved view and the sort (`CollectionsController`, `CollectionListing`, `CollectionGrid`, `CollectionTable`, `CollectionFilter`, `CollectionFilter::Place`, `CollectionTable::Sort`) (spec 004 Story 11; spec 006 Stories 1–3; spec 033; spec 037; spec 048; spec 065 Story 6).
- Bulk mode: the selection, Set condition, Move to…, the bulk removal and its Undo (`BulkSelection`, `Collections::SelectionsController`, `Locations::SelectionsController`, `Decks::SelectionsController`, `BulkModeShortcut`, `Lot::ConditionChange`, `Lot::BulkMove`, `Collections::MovesController`, `BulkRemoval`) (spec 006 Stories 4–8; spec 032 Story 7; spec 041; spec 059; spec 065 Story 3; spec 067).
- Number entry: `NumberEntry`, `NumberEntry::Line`, `NumberEntry::LineForm`, `NumberEntry::SetChoice`, `/collection/number_entry` (spec 026, all but the list being left out of the export; spec 034; spec 065 Story 4).
- Locations: `Location`, `Location::Name`, `Location::Holdings`, `/locations` (`LocationsController`, `Locations::RemovalsController`, `Locations::SelectionsController`), which knows places only since decks exist (spec 029, all but its format, export, preview and apply parts; spec 032 Stories 4, 5; spec 059; spec 062 AC-3.8, AC-4.8).
- Decks as locations and the Decks pages: the kinds of `Location` (`place`, `deck`, `deck_zone`), `Deck`, `Deck::Creation`, `Deck::FormatChange`, `Deck::Listing`, `Deck::Page`, `Deck::Proxy`, `Deck::Proxy::Addition`, `Location::Placement`, the format seam `Catalog::Formats` (MTG's registration is `MTG::Collecting::FORMATS`) and the deck page's seam `Catalog::DeckCards` (MTG's answer is `MTG::Collecting.deck_card`), `DecksController`, `Decks::RemovalsController`, `Decks::FormatsController`, `Decks::ProxiesController`, `Decks::Proxies::RemovalsController`, `/decks`, and the one label "Deck › Zone" wherever a lot's place is shown (spec 062 decisions 1–3, 5–7, Stories 1–5, FR-1, FR-2, FR-4, AC-9.1–AC-9.6, AC-9.11; spec 064; spec 066; spec 068; ADR 0028). How an export, a preview and an apply cover decks and zones is data portability's.
- Adding a card to a deck from its card page: `DeckAdditionsController`, `Deck::Addition`, `Lot::FreeCopies`, `DeckAdditionsHelper`, the free-copies rule and the take (spec 071).
- Tenant isolation for all of these (spec 004 AC-12.1–AC-12.3, AC-12.5; spec 006 Story 8; spec 029 Story 4; spec 032 Story 6). That every collection table carries `account_id` with a foreign key and an index (spec 004 AC-12.4) is [tenancy and accounts](tenancy-and-accounts.md)'.

**Neighbours:**

- How lots and locations leave and enter an instance (the export, format version 4, the import preview and the apply), and that the number-entry list, the scanner sitting, bulk selections and bulk removals' undo are working state left out of the export and cleared by an apply that writes a lot: **[data portability](data-portability.md)**. This doc uses only that an apply replaces lots and locations in one transaction and keeps the lot identity and the location rules stated here.
- Catalog entries, sets, search, the card page's catalog content (details, legality, the printings list's catalog rows) and each collectible's vocabulary (`Catalog.collecting_for`: finishes, `finish_order`, special finishes, conditions): **[catalog core](catalog-core.md)**. This doc uses the vocabulary as given.
- The scanner's sitting adds copies through `Lot.add!` with the sitting's condition and into the sitting's place or zone, unspecified and unplaced while it has none, and has its own Undo (spec 009; spec 040 decisions 2, 4; spec 042 decisions 2, 4): **[scanner](scanner.md)**.
- `Current.account`, users, sessions, sign-up, the admin users page (which shows each account's copy count) and deleting a user with their account: **[tenancy and accounts](tenancy-and-accounts.md)**. This doc uses that every collection query goes through `Current.account` and that a session ending discards its bulk selection and Undo.
- The patterns these pages are built from (`ItemTile`, `TileAdd`, `UnownedTile`, `CollectionPage`, `CollectionTable`, `ViewSwitchForm`, `SortHeader`, `BulkForm`, `BulkConfirmPage`, `ChoicePage`, `StatusAction`, `ItemPage`, `NumberEntry`, `Locations`, `DecksIndex`): **[design system](../design-system/README.md)**.

## Glossary

- **Printing / entry:** one catalog entry: one set, number and language (`Catalog::Entry`). **Card:** the gameplay identity its printings share (`Catalog::Identity`) (spec 004 Users and Context).
- **Copy / item:** one physical card; the counts on the collection page count copies and call them items (spec 004 AC-11.1; spec 006 Users and Context).
- **Lot:** copies of one printing with the same finish, condition, price paid and place, owned by one account, with a quantity of 1 to 9,999 (spec 004 FR-6; spec 032 decision 1; ADRs 0019, 0025).
- **Identity:** those five values; unspecified equals unspecified. Its text form is `lots.lot_key` (spec 004 FR-6, AC-12.5; spec 032 FR-1).
- **Location:** a row of `locations`, of one of three kinds (`Location::KINDS`): a *place*, which is a name and nothing else (the only kind there was; spec 029 decision 4), a *deck* and a *zone* (spec 062 decision 1; ADR 0028).
- **Place / unplaced:** a place is a location of kind `place` (spec 062 Terms). Where a lot is kept is a place, a zone or none; an unplaced lot reads "No location" on screen and `null` in a file (spec 032 Terms, decision 2; spec 062 decision 1).
- **Deck / zone / top-level location:** a deck is a location of kind `deck` with one `decks` row (the collectible type and the format) and no parent; a zone is a location of kind `deck_zone` whose `parent_id` is a deck and whose `zone` is the stable key of one zone of the deck's format (`main`), its `name` the text shown for it (`Main`), stored when the deck is made. A top-level location is a place or a deck (spec 062 Terms, decision 1).
- **Format / zone key:** a collectible type's named set of zones, registered through `Catalog::Formats`; the format's key is unique within its type and a deck stores both. `considering` is the one zone key the core names, because every format has that zone, and it is the zone a change of format moves a dropped zone's lots into (spec 062 decision 2, FR-2; spec 064 decision 3; ADR 0028).
- **Label:** "Deck › Zone" (`Location::ZONE_SEPARATOR`), how a zone is shown wherever a place is, from `Lot#place_label` to `Location#label` to `Location::Placement.label`; a place's label is its name (spec 062 decision 6, AC-5.4).
- **Proxy:** one row of `deck_proxies` (`Deck::Proxy`): a printing and a finish with a quantity of 1 to 9,999 in one zone, for a card the deck needs and the collector doesn't own; unique per zone, printing and finish; never a lot, so never counted as owned (spec 068 decision 1). **Cards:** a deck's owned copies plus its proxies, in every zone, Considering included (spec 060 decision 12; spec 068 decision 7).
- **Free copy:** a copy of a card, of any printing, in no deck zone (unplaced or in a place); Considering counts as a deck zone, and a proxy never counts either way (spec 071 decision 4; spec 057 FR-3; `Lot.free`, spec 070; the card's free lots in take order are `Lot::FreeCopies`).
- **Name / comparison key:** a location's name after normalisation, and its Unicode full case folding, which is unique among an account's top-level locations, and a zone's within its deck (spec 029 decision 5; spec 062 decision 3).
- **Merge:** copies that reach an identity a lot already has join that lot instead of making a second (spec 004 AC-7.4, AC-9.3, AC-10.2).
- **Quick add:** one copy of a printing, from a tile or a printings row, with finish, condition, price paid and place unspecified (spec 004 Story 7).
- **Tile:** one grid cell, one owned printing summing its lots. **Row:** one table row, one lot. **Place line:** the text a tile or row shows for its places (spec 033 Terms).
- **Saved view:** the collector's choice of grid or table (`users.collection_view`) (spec 006 FR-1).
- **Bulk mode:** the table with checkboxes and the bulk bar, entered with `Edit many` (or from a location's or a deck's refusal page, spec 059, spec 067) and left with `Done` (spec 006 Story 4).
- **Picker / choice:** a picker is a select in which a collector chooses where a copy is or goes (the lot form's Location, Move copies' To, bulk Move to…'s To, number entry's Location, the sitting's Location); a choice is a place or a zone, never a deck's own row; the filter's select offers the same choices (spec 065 Terms, decision 1).
- **Destination:** the place or zone a move sends lots to, one of the account's places or zones, or none; a deck's own row never is one (spec 065 decision 7; spec 041 Terms). **Already there:** a selected lot whose place is the destination (spec 041 Terms).
- **Selection:** the lots ticked in bulk mode, stored per session under one name filter, location filter and sort; **every matching lot** is a state of its own, with exceptions (spec 006 FR-4; spec 037 decision 5).
- **Location filter:** the collection's `location` parameter: all (absent or empty), `none` (unplaced lots), one of the account's places or zones by id, or `deck:<id>` for a whole deck (every zone of it); a deck's own id without the prefix, a zone's id with it, another account's and a removed one read as all; its canonical value is `""`, `"none"`, an id of at most 18 digits without leading zeros, or `deck:` and such an id, anything else reading as all (`CollectionFilter::Place`; spec 037 decision 1; spec 065 decision 4, which supersedes spec 062 AC-5.2 for a zone's id).
- **Undo record:** what a bulk removal keeps so it can be undone once (spec 006 FR-6).
- **Number entry / list / line / line key:** the "Add by number" page; the account's added lines until Done; one submitted number, quantity, finish and place; the random token that makes a line add at most once (spec 026 Terms, decision 10).
- **Holdings:** what an account's lots hold in one location: lots and copies; a deck holds what its zones hold together (spec 032 P1, P2; spec 062 AC-3.3).
- **Collection mark:** `from=collection` on a card page URL, which makes its breadcrumb and current section Collection (spec 004 AC-8.9).

## Invariants

- **An account never holds two lots of one identity.** The identity is the printing, finish, condition, price paid and place; the unique index on `lots (account_id, catalog_entry_id, lot_key)` backs it in the database (spec 004 FR-6, AC-12.5; spec 032 decision 1; ADR 0025).
- **The key ends in the place's id, not its name.** `lot_key` is `finish|condition|price_paid_cents`, and for a placed lot `|location_id` after it, so an unplaced lot's key is what it was before locations and renaming a location keeps every key (spec 032 decision 2, FR-1; ADR 0025). Five places build a key and all carry the place: `Lot.key_for`, the SQL in `Lot::ConditionChange#update_alone!`, the SQL in `Lot::BulkMove#move_alone!`, `BulkRemoval#identity` with its `insert_all`, and the apply's attribute builder for `upsert_lots!` (spec 032 Notes for the plan; spec 041 FR-2, which adds the move's; `spec/models/lot/bulk_move_spec.rb` proves the move's equals `Lot.key_for`'s; [data portability](data-portability.md)). A lot in a zone is keyed by the zone's id exactly as a lot in a place is, so none of the five changed, and a spec per builder proves it (`spec/models/lot_spec.rb`, `condition_change_spec.rb`, `bulk_move_spec.rb`, `bulk_removal_spec.rb`, `collection_import/apply_spec.rb`; spec 062 decision 1, Notes for the plan; ADR 0028). Rolling back spec 032's migration is refused while any lot is placed (spec 032 NFR Reliability; ADR 0025).
- **A lot holds 1 to 9,999 copies,** in the model and in the `lots_quantity_range` check constraint. The cap is per lot, so per place (spec 004 FR-6; spec 032 decision 1, AC-1.5).
- **Every way of adding or changing lots merges into the identity and keeps the cap, all or nothing:** `Lot.add!` (quick add, "Add a copy", number entry, the scanner, a merging Undo), `Lot#revise!` (an edit; the other lot survives), `Lot::Move`, `Lot::ConditionChange`, `Lot::BulkMove` and `BulkRemoval#undo!` (spec 041 decision 4). A scanner add whose sitting condition the printing's vocabulary doesn't know is refused before anything is written (spec 042 decision 5, AC-4.5). A change that would pass 9,999 changes nothing (spec 004 AC-7.3a, AC-9.3, AC-10.2; spec 006 AC-6.4, AC-7.5; spec 032 AC-1.5, AC-2.4, AC-3.6, FR-1). `Lot.add!` retries once after losing a race on the unique index, so a race merges instead of failing (spec 004 AC-12.5).
- **A lot is in one of its account's places or zones or in none, never another account's and never in a deck's own row.** `Lot` validates a new place against its account and refuses a deck's row, which the database can't state without a trigger, so every write path takes its ids from a lookup that can't return one (spec 062 decision 1, AC-5.3; ADR 0028); the lot form, Move copies and bulk Move to… look the place or zone up through `Location.find_placeable!`, called on `Current.account.locations` (the `placeable` scope: kinds `place` and `deck_zone`, the parent loaded so a message can read the label; text that isn't an id of at most 18 digits is 404 before any cast, so "12abc" is never read as 12) and answer 404 for any other id, a deck's own row and another account's location included; the scanner sitting's "Set" applies the same scope and id guard and answers 422 with its own sentence, and a request's id is never trusted to be a location of the account (spec 065 decision 1, AC-1.7, AC-2.4, AC-3.3, AC-5.3, AC-8.4; supersedes spec 062 AC-5.2, which refused a zone's id); number entry shows a field error instead, because it is a form the collector returns to, reading the id among the account's `Location::Choices` (spec 032 decision 6, AC-1.7, AC-2.7, AC-3.9; spec 034 decision 5, NFR Security; spec 065 AC-4.3).
- **No lot is ever in a missing location.** A location that holds a lot can't be removed: the controller refuses it and the foreign key from `lots.location_id` is `on_delete: :restrict` (spec 032 decision 3, AC-5.4, AC-5.5; ADR 0025). Removing an empty location changes no lot (spec 029 decision 3, AC-3.4); it clears the place of a scanner sitting that names it, through `scanner_sittings.location_id`'s `on delete set null`, whether the locations page or an import apply removes it, and the next add is unplaced (spec 040 decision 7, AC-3.2). Deleting an account deletes its lots before its locations; that depends on the order of `Account`'s `has_many` declarations, which `spec/models/account_spec.rb` guards (spec 032 AC-6.6); `decks` is declared after `locations`, and the foreign keys cascade a deck's zones and `decks` row from its location (spec 062 AC-9.6). A deck whose zones hold any lot can't be removed either, by the page and by the same foreign key (spec 062 decision 7, AC-3.4, AC-3.5).
- **Only some ways of adding choose a place or a zone.** "Add a copy", "Edit copy", Move copies and number entry (spec 034) do, and the scanner adds with the condition and into the place or zone chosen once for its sitting, both read on the server inside each add, or unspecified and unplaced while the sitting has none (spec 040 decisions 2, 4, AC-1.3, AC-1.5; spec 042 decisions 2, 4, AC-1.3 to AC-1.5; spec 042 supersedes spec 040 decision 4's "condition (none)"); bulk Move to… chooses one place or zone for every selected lot (spec 041; spec 065 decision 7); quick add adds copies unplaced, and the other bulk actions keep each lot's place, merging into the lot of their identity in that place (spec 032 decision 5, AC-7.2; spec 041; spec 034; spec 040 supersedes AC-7.2 for the scanner).
- **Location names follow one definition,** `Location::Name`: NFC, White_Space trimmed and collapsed to one U+0020, Cc and Cf refused, 1 to 60 code points; the comparison key is unique among an account's top-level locations (places and decks share one name space) in the model and in the partial unique index on `locations (account_id, name_key)` where `parent_id IS NULL`, and a zone's within its deck in the partial index on `(parent_id, name_key)`, so every deck can have a "Main" (spec 062 decisions 1, 3; ADR 0028); check constraints bound the name's length, and one definition serves a place's, a deck's and a zone's name (`Catalog::Formats.verify!` checks the registered zone names against it at boot). `spec/models/location/name_parity_spec.rb` proves the model, the schema and the format document agree for every scalar value (spec 029 decisions 5, 9, AC-7.8).
- **An account has at most 500 top-level locations,** places and decks together; zones never count, and the cap holds under racing adds because write transactions serialise (spec 029 decision 7, AC-1.13; spec 062 decision 3, AC-1.7a, AC-1.9, AC-5.9).
- **A deck and its zones are written, renamed, changed and removed as one thing.** Creating writes the deck's location, its `decks` row and one zone per zone of the format, in the format's order, in one transaction; a failure part way leaves none. The tree is one level deep: a zone's parent is a deck of its account, a deck and a place have no parent, only a zone has a `zone` key, and the schema states what it can in named check constraints (`kind`, `parent_id` set exactly for a zone, `zone` set exactly for a zone) (spec 062 AC-1.3, AC-1.11, AC-9.4, AC-9.5; ADR 0028). A change of format rewrites the zones in one transaction too (see "A deck"); a failure part way leaves the deck, its zones, its lots and its proxies as they were (spec 064 AC-2.8; spec 068 AC-6.7). A rename, a removal or a change of format never re-checks the old format or the old zone keys, so a deck whose registration the instance lost can still be renamed, removed and changed to a registered format (spec 062 Error Scenarios; spec 064 decision 2, AC-1.7).
- **Every list of locations says which kind it means.** Places only (`Current.account.locations.places`): the locations page and its counts, the export's `locations` and the import's held and file locations. Places and zones (`Location::Choices`, which reads the account's locations in one statement, and `Location.placeable`): every picker (the lot form's select, Move copies' and bulk Move to…'s destinations, number entry's select, the scanner sitting's place) and the collection filter's select and value, which adds `deck:<id>` for a whole deck. **Spec 065 widens, on purpose, what spec 062 decision 1 and ADR 0028 kept to places only "until the pickers and the filter learn zones" (#252): every picker and the filter now list places and zones, and a write that names a location looks it up through `Location.find_placeable!`; a deck's own row is in no list a collector chooses from, in no destination and in no filter value of its own id** (spec 065 decision 1, FR-1). Every kind: `Lot`'s validation, the card page's overview and rows, the collection grid's and table's place reads, a bulk removal's undo, the number-entry and scanner lists' lot places, the export's lot rows, the import's held lots and its lot placement (a place key is resolved among places only and a zone by its (deck key, zone key) pair), and the refusal pages. A spec per surface keeps a deck's own row out of the choices (spec 062 decision 1, AC-5.1; spec 065 AC-8.1–AC-8.4; `spec/models/location/choices_spec.rb`, `spec/requests/deck_zone_pickers_spec.rb`).
- **A proxy is never owned and changes only by hand.** No way of adding, moving, editing, bulk-moving, typing, scanning or removing a copy, no import of lots and no catalog refresh creates, changes or removes a proxy; the writers are the add, change and remove pages, a change of format, a deck's removal and an import that carries proxies. A proxy is in no count of owned copies: not the collection's, the card page's or the Decks page's Owned (spec 068 decisions 1, 11, AC-4.1–AC-4.3; closes spec 065 decision 11).
- **A zone is shown as "Deck › Zone" everywhere a place is, from one label,** never by the zone's name alone: the card page's "Your copies", the lot's action labels, the collection's tiles, rows and phone line, bulk mode, the removal refusal pages, the number-entry and scanner lists and the import preview. A list preloads `location: :parent` so the label costs no query per lot (spec 062 decision 6, AC-5.4).
- **No path unplaces a lot in a zone by accident.** "Edit copy" shows the Location select with the lot's zone chosen, so a save keeps it, and a lot is moved out of its zone only by choosing another place, zone or "No location" there or in Move copies or bulk Move to…, which offer zones, places and "No location" (a lot already in the chosen zone is "already there", as for a place); bulk Set condition, bulk removal's Undo and number entry's and the scanner's Undo keep each lot's zone as they keep a place; under the collection filter a lot in a zone is in neither "No location" nor a place, and shows under its zone, under "<Deck> (all zones)" and under "All locations" (spec 065 decisions 5–7, AC-1.6; supersedes spec 062 decision 6 and AC-5.5–AC-5.7a for these surfaces; spec 062 AC-5.7b, AC-5.8 stand).
- **Everything is scoped to `Current.account`.** Another account's lot, location or number-entry line answers 404, unchanged (spec 004 AC-12.2; spec 026 AC-3.8; spec 029 AC-4.1; spec 032 AC-6.1); lot ids in a bulk submission that aren't the account's are ignored, not answered with 404 (spec 006 AC-8.1), while a foreign location id for a bulk move is 404 (spec 041 AC-2.3, AC-5.2); an Undo of another session's removal is 404 (spec 006 AC-8.3). No form takes an account, user or admin value (spec 004 AC-12.3; spec 006 AC-8.4; spec 029 AC-4.3).
- **The operator sees no collection detail.** No admin page shows a location, its name, a lot's place or a per-location count (hosted-door rule 2; spec 029 AC-4.5; spec 032 AC-6.4); the admin users page's per-account copy count is [tenancy and accounts](tenancy-and-accounts.md)'.
- **A catalog refresh never changes a lot, a selection or an undo record,** and lots of retired printings are kept, shown, restored and can be quick-added (spec 004 FR-6, AC-11.9, Error Scenarios; spec 006 AC-2.7, AC-7.7, NFR Reliability).
- **The core names no collectible.** Finishes, the finish order, special finishes and conditions come from the vocabulary; the core stores finish and condition as values it doesn't interpret (spec 004 FR-6; spec 006 FR-2; spec 026 FR-1; spec 029 FR-2; spec 033 FR-6). `spec/number_entry_core_spec.rb` checks number entry's files and `spec/import_apply_core_spec.rb` the location, Move copies and bulk Move to… files (spec 041 FR-4) and the refusal page's shortcut controller, `app/controllers/locations/selections_controller.rb` (spec 059 FR-3), and the shortcut's shared definition, `app/controllers/concerns/bulk_mode_shortcut.rb` (spec 067 FR-3); `spec/deck_core_spec.rb` lists the 48 deck files, spec 068's proxy files among them (AC-8.7), (the decks controllers, `Decks::SelectionsController` among them, and views, `Deck`, `Deck::Creation`, `Deck::Listing`, `Location::Placement`, `Catalog::Formats`, the deck helper and icon, the import's deck files, and the picker's `Location::Choices` and `LocationChoicesHelper`, spec 065 AC-8.3) and fails if one names `mtg`, `scryfall` or `magic`, one of MTG's eight format keys, or the zone keys `sideboard` and `commander`: the one zone key core code names is `considering` (spec 062 AC-9.11, decision 2); `spec/collection_places_core_spec.rb` lists the seven core files spec 033 changed (the grid, table and filter models, the lots helper, and the tile, table and row-cell views) and fails if one names `mtg`, `scryfall` or `magic` in any spelling, `scryfall_id` included (spec 048 AC-2.4); no core guard lists `Lot`, `LotsController`, `Lot::Form`, `Lot::ConditionChange`, `BulkRemoval`, `BulkSelection`, `CollectionTable::Sort` or the collection views beyond those three. Every core guard (`spec/*_core_spec.rb`, and `spec/export_format_document_spec.rb`'s check that the format document and its schema name no collectible outside the types section) matches a type or source name (`mtg`, `scryfall`, `magic`) anywhere in a word, so `scryfall_id` and `MTGPrinting` fail it; a word that is also part of ordinary words (`art`, and the finish names `foil`, `nonfoil` and `etched`) is matched as `(?<![a-z])term(?![a-z])`, so `art_thing` and `foil_label` fail it and `start` and `foiled` don't. Known limit: a CamelCase compound such as `FoilLabel` or `ArtBuild` passes. `\b` is not used, because `_` is a word character ([#209](https://github.com/plainprogrammer/Collector/issues/209)). A new guard proves it can fail with a temporary identifier-shaped name, not only the bare word.
- **Lists cost a bounded number of queries,** independent of tiles, rows, lots or locations: locations add two statements to the grid (one read of the account's locations, places and zones together, which also serves the filter's select and `place_column?`, and the grouped read, which a location filter skips) and two to the table (the locations read and the location preload; a lot in a zone adds the preload of its deck, one more, spec 062 AC-5.4); an account with no place no longer pays an extra `exists?` for `place_column?`, which follows the same gate as the pickers, and every picker reads the account's locations in one statement whatever the number of places, decks and zones (`Location::Choices`; spec 065 decision 3, AC-6.10, AC-8.2), the locations page two grouped statements for its counts, the Decks page a bounded number (the decks read with their locations, and one grouped read each of the copies and of the proxies in all their zones; spec 062 AC-4.7; spec 068 AC-5.3), a number-entry add a fixed number (spec 004 NFR; spec 006 NFR; spec 026 NFR; spec 029 NFR; spec 032 NFR; spec 033 AC-3.2, FR-2, whose `verification.md` records the two statements against the NFR's "one").
- **Every page works without scripting;** scripting only enhances (in-place quick add, the live selection count, the header's mixed state, Esc for `Done`, "/" to search) (spec 004 FR-12; spec 006 NFR; spec 026 Story 5; spec 029 AC-1.12; spec 032 AC-3.12).
- **No request marked as a prefetch changes state:** not the saved view, a selection or an Undo record; `Edit many`, `Done` and the refusal pages' (a place's and a deck's) "Move them in bulk mode" are buttons, never links; the shortcuts have no GET route at all (spec 006 FR-1, AC-1.10, AC-4.1; spec 059 AC-1.4, AC-4.5; spec 067 AC-1.4, AC-4.5).
- **Price paid is stored exactly in cents** and shown in the signed-in account's currency, `accounts.currency`, one of the 20 codes `Collector::Currency::SYMBOLS` knows, read through `Account#currency_unit` (spec 038 decisions 1, 8, FR-4). A new account starts at the instance default, `COLLECTOR_CURRENCY` (default USD); changing it later changes no account (spec 038 decision 2, AC-3.3). A collector changes theirs on the Currency page (`/currency/edit`, linked from More and the account menu), which converts nothing: `price_paid_cents` and `lot_key` stay (spec 038 decisions 4, 5, AC-1.5). No code but `Account` and the initializer reads the default, and `spec/currency_reads_spec.rb` guards it (spec 038 decision 2). The upgrade that added the column gave every existing account the instance's `COLLECTOR_CURRENCY` of that moment, refusing an unsupported code rather than falling back (`20261103100002_set_account_currency_from_the_instance.rb`; spec 038 decision 3, Story 4), and the upgrade proof's next seed holds an account in EUR (spec 038 AC-4.7).
- **An import apply that writes a lot ends the working state that points at lots:** it deletes the account's bulk selections, supersedes every undoable bulk removal of any session, and destroys the number-entry list (and the scanner sitting) (`CollectionImport::WorkingState`; spec 028 decision 7; spec 029 decision 11; [data portability](data-portability.md)).

### Moving copies (`Lot::Move`)

It moves one lot; many lots at once is Move to… in bulk mode (spec 041).

The page asks for Copies (1 to the lot's quantity, set to it) and To ("No location", unless the lot is unplaced, then "Places" and "Decks" as on the forms, the lot's own place or zone left out; a deck's own row is never a destination, and a lot in a zone is offered "No location", every place and every other zone: spec 065 AC-2.1, decision 7, which supersedes spec 062 AC-5.6 where it says zones aren't offered). A move into a zone merges, splits and caps as a move to a place does, and its notice reads "Moved <n> × <name> (<SET> · <number>) to Izzet Tempo › Main." (spec 065 AC-2.2). The card page's lot menu offers it; the table's menu doesn't (spec 032 AC-3.1). Inside one write transaction the lot is read again and the move is judged against it, so a second submit of a stale form can't create or lose copies (spec 032 plan review round 2, Major 1, recorded as "M1 (round 2)" in its `verification.md`):

### A deck

The Decks section is the second link of the header and of the tab bar, after Collection (spec 062 AC-4.1; the five links and their fit are the [design system](../design-system/README.md)'s). A deck's URLs carry its location's id, not the `decks` row's, so a place's or a zone's id is 404 on them ([tenancy and accounts](tenancy-and-accounts.md); spec 062 decision 4, AC-3.8).

`GET /decks` lists the account's decks by comparison key, then name: the head reads "6 decks · 379 cards" (the cards of all their zones, owned plus proxy, Considering included), the table has Deck, Format (the format's name, its key when the instance no longer registers it), Cards (owned plus proxy), Owned and Proxy (the dashed tag, or a muted dash) and each row's Rename, Change format and Remove; below 640px of its container Format, Owned and Proxy are hidden and the line under the name reads "<Format> · <n> owned" and the Proxy tag for a deck that has proxies. With no deck the page says "No decks yet. Add a deck to start building one." and keeps "New deck" (spec 062 AC-4.3–AC-4.6, decision 5). The deck's name is a link to the deck page (spec 066 decision 1, AC-1.5; spec 062 decision 5 kept it plain text until #253; the page's markup is `DecksIndex` in the design system).

`GET /decks/:id` is the deck page (spec 066, #253; the markup is `DeckPage`): the id is the deck's location id and another account's deck, a place's id, a zone's id and an id that is not digits only are 404 ([tenancy and accounts](tenancy-and-accounts.md); AC-1.2). It reads only, through `Deck::Page`, and adds no way to add or move copies (AC-4.2). The head reads "<Format> · 69 cards · 58 owned · 11 proxy" (every zone, Considering included; cards are owned plus proxy) and a zone's head "12 cards · 12 owned · 0 proxy" with "Add a proxy", a link, at its end (spec 068 decisions 5, 7, AC-2.3). The zones are in the format's registered order, a zone the format does not list and every zone of an unregistered format after them by id, so a zone a change of format added later still reads Main, Sideboard, Considering (decision 3). A zone is one table, one row per printing: its lots of every finish, condition and price are summed into Owned (decision 2); the columns are Card, Cost, Owned, Proxy, Total and the row menu: a row with proxies shows the Proxy tag (the sum of its finishes' proxies) and a menu of "Change proxy count" and "Remove proxy" (the finish named when a row has proxies of two finishes), Total is owned plus proxy, a printing with a proxy and no copy is a row of Owned 0, and a row with no proxy has an empty menu cell (spec 068 decisions 5, 8, AC-2.1, AC-2.6; spec 066 decision 7 and 9 stand for the rest), and below 640px of the table's container Owned and Proxy are hidden (spec 060 decision 9, decision 7). Rows are grouped by the collectible's groups and ordered by the shown name, set code, collector number as a person reads it (`Catalog::Entry::NUMBER_HAS_DIGITS_FIRST`, `NUMBER_VALUE`), number text and language (decision 3, `Catalog::Entry::DISPLAY_NAME_SQL`). The card's name links to the card page in the collection's context at its copies, where Move copies per lot lives (decisions 9, 10). `Deck::Page#zones` runs at most 6 statements (3 for a deck with no lot and no proxy: the zones, the lot sums, the proxies, then the entries, their sets and one extension read per type; spec 068 AC-2.10) and the controller 2 more for the deck, however many zones, rows, lots and proxies there are (AC-2.10). The right column stays empty for the shape panel (#256).

The page's collectible part is a second optional answer of the collecting vocabulary, beside `formats`: `deck_card(entry, format_key)` returns a `Catalog::DeckCards::Answer` (group, position, legality word, whether a `deck_cost` partial draws the cost); the contract is written in `Catalog::DeckCards`' comment, and a vocabulary that answers nothing gets one flat table, a muted dash and no marker (spec 066 decision 5, AC-6.1). Magic groups by the first face's type line: a Creature is a Creature, otherwise a Land is a Land, otherwise the first of Planeswalkers, Battles, Instants, Sorceries, Artifacts, Enchantments, then Other (decision 6, `MTG::DeckGroups`); the cost is the first face's (decision 11, `mtg/printings/_deck_cost`); the legality marker is the printing's stored legality in the deck's own format, nothing for Casual or an unregistered format, "Not legal" for a missing entry, written twice and shown once by width (decision 8, `MTG::Collecting::LEGALITY_FORMATS`).

### The collection page

`GET /collection` shows the grid or the table: the `view` the URL names when it is `grid` or `table`, else the saved view (grid until one is chosen). A page outside bulk mode whose URL names a valid view saves it for that user, unless the browser marked the request a prefetch; an unknown view shows the saved one with 200 (spec 006 FR-1, AC-1.2–AC-1.6, AC-1.10). The page shows "My collection", "<copies> items · <unique cards> unique", the actions "Add by number", "Scan cards" and "Add items", the filter bar (name search, the Location select while the account has a place or a zone, view switch, `Edit many`), and the count on the line under it ("<matching> of <total> items" when filtered) (spec 004 AC-11.1, AC-11.4; spec 006 AC-1.1, AC-4.1; spec 009 AC-8.2; spec 026 decision 1). An empty collection shows "No cards in your collection yet. Search for a card or add cards by number to start adding." and no filter bar, view switch or `Edit many`, and so does a bulk URL or `Edit many` on it (spec 026 decision 1; spec 006 AC-1.9, Error Scenarios). A filter that matches nothing shows "No cards in your collection match "<query>"." and "0 of <total> items"; in bulk mode the bar reads "0 of 0 selected" with no header checkbox (spec 004 AC-11.5; spec 006 AC-5.9). Under a location filter the sentence names the place, the zone's label or the deck: "No cards in your collection are in “<name>”." ("…in “Izzet Tempo › Main”.", "…in “Izzet Tempo”." for a whole deck), "No cards in your collection are without a location.", or with a name filter `… match "<query>" in “<name>”.` and `… match "<query>" without a location.` (spec 037 AC-1.6, AC-2.2, AC-3.2; spec 065 AC-6.4, decision 9).

- **Location filter:** a FilterSelect in the filter bar ("All locations" and "No location" outside any group, then an `optgroup` "Places" in the locations page's order, then an `optgroup` "Decks" in which each deck has first "<Deck> (all zones)", valued `deck:<id>`, and then its zones as "Deck › Zone"; flat while the account has no deck) with a Filter button, in both modes, shown only while the account has a place or a zone; otherwise a `location` parameter is ignored (spec 037 decision 6, AC-1.1, AC-6.1; spec 065 AC-6.1, decisions 2–4, which supersede spec 037 decision 1's three kinds of value and decision 6's list, "never a deck or a zone"). A lot in a zone is in neither "No location" nor a place; it shows under its zone, under "<Deck> (all zones)" (every lot in any zone of the deck, and no other deck's or place's) and under "All locations" (spec 062 AC-5.8; spec 065 decision 5, AC-6.2, AC-6.3). It joins the name filter with AND; the grid, table, pagers, counts and bulk selection all narrow through `CollectionFilter.lots`, and `Place.apply` turns `deck:<id>` into a join on the lot's location with `parent_id = <id>` tied to the lot's own account, so another account's deck id matches no lot (spec 037 decision 2, FR-2; spec 065 decision 4, AC-8.4). The page resolves the URL's value against the account's choices and decks: another account's id, a removed one, a deck's own id without the prefix, a zone's or a place's id with it, an id with leading zeros or a malformed value is all, with 200 and nothing of another account shown or named (decision 7, AC-6.2; spec 065 AC-6.5). Every link and form that carries `q` carries `location` (left out for all); a view saved from a URL doesn't save the location, and the card page is unchanged (spec 037 FR-3, AC-4.1–AC-4.3).

- **Filter:** part of a card's name or localized name, case-insensitive for ASCII, `%` and `_` literal, at most `Catalog::Search::MAX_QUERY_LENGTH` characters; it is in the URL (spec 004 AC-11.4, AC-11.5).
- **Grid:** one tile per owned printing, ordered by card name, then release date newest first, set code, collector number and language; 120 per page; out-of-range pages fall back with 200. A tile shows the image, the total quantity ("×1" too), one finish badge for the special finishes its lots have, the printed name (localized only for a non-English printing), `SET · number`, the language and its place line (spec 004 AC-11.2, AC-11.3; spec 033). Under a location filter, a deck's included, a tile sums only the matching lots (quantity and badges, all the deck's zones under "<Deck> (all zones)") and shows no place line; a printing with no copy there has no tile, and the table under a deck filter shows each row's "Deck › Zone" in its Location column, which is where a collector tells Main from Considering (spec 037 decision 3, supersedes spec 033 AC-1.8 for that filter; spec 065 decision 13, AC-6.3).
- **Table:** one row per lot, 120 per page, with name (thumbnail and printed name, linking to the card page with the collection mark), set · number, language, finish, condition (short form), quantity, Location, price paid and a menu ("Edit copy", "Remove"). Below 640px only name, quantity and the menu show, and a line under the name gives set · number, finish, condition, language and the place (spec 006 AC-2.1, AC-2.8; spec 033 AC-2.1, AC-2.2). For containers of 640 to 699px the name is cut to one line with an ellipsis when the other columns leave it no room (#208, below).
- **Sort (table only):** name, set · number, condition (the vocabulary's scale), quantity or price paid, by an allowlist in `CollectionTable::Sort`; the default order is the grid's (collector numbers compare numerically, [catalog core](catalog-core.md); #204), then finish order, condition scale and price, unspecified last, then id, which breaks every tie. The first click on Name sorts descending; a new sort returns to page 1. An unknown column is the default order with 200; a known column with an unknown direction is that column ascending (`CollectionTable::Sort.parse`, pinned by `spec/models/collection_table/sort_spec.rb`), where spec 006 AC-3.7 says the default order for both. The Location column is not sortable (spec 006 Story 3, FR-3; spec 033 decision 4).
- **Place line:** while the account has no place and no zone there is no place line and no Location column; the gate is the one the selects, the filter, Move to… and the form's field use, "a place or a zone" (`CollectionFilter#place_column?` is `choices?`), so an account with a deck and no place shows the column, the line, the selects and the filter, and no second read is made to decide it (spec 065 decision 3, AC-6.10, which supersedes spec 062 AC-5.8a). Otherwise a tile shows the place with most copies, a zone as "Deck › Zone" and sorted under its deck's name, then "+N more" for the printing's other places, unplaced counting as one (ties: comparison key, unplaced last); an unplaced lot or tile reads "No location" in secondary ink, and the phone row line leaves "No location" out. A tile's line is one line with an ellipsis and keeps its "+N more". A row's wraps instead: the phone line under the name wraps below 640px, and the wide Location cell holds the name in a `c-table__place-name` span of at most 20rem that wraps it, so a long name makes a taller row and never scrolls the page sideways; both break a name with no space inside it. The cap is on the span because Firefox ignores `max-width` on a table cell. Near the 640px breakpoint the Location column shrinks to its longest word, so a 60-character name takes up to five lines there (spec 048 decisions 1–3; a 60-character name measured in headless Firefox at frames of 740 to 1280px). The phone line's wrap rule is the `c-table__sub` rule of every table inside `.c-collection` below 640px, an account with no location's included, where a line wider than its cell wraps instead of scrolling the page: spec 048 AC-1.7's line ("MH3 · 146 · Foil · NM · EN") fits one line at 360px and 390px, a five-character code alone ("PMH3A · 146 · Foil · NM · EN", 153px) still fits a phone's 360px with about 8px to spare, and a line of The List ("PLST · PCY-132 · Etched · NM · EN", 184px against a room of 161px) wraps by 23px. Spec 048 AC-1.8's claim that a five-character code wraps at 360px held only with a classic scrollbar's 345px of content; spec 061's example measures the margin at a phone's 360px whatever scrollbar the browser draws (spec 033 decisions 1–3, AC-1.1–AC-1.6, AC-2.2; spec 048 decision 4, AC-1.1–AC-1.7; spec 061 AC-1.1, AC-1.2).

### Bulk mode

`Edit many` (a button) clears any stored selection and opens the table in bulk mode (`bulk=1`) with nothing selected, the same filter and sort; the view switch is inert (Table pressed, Grid disabled); rows have no menu (spec 006 AC-4.2, AC-4.3). A location's refusal page starts it the same way with every matching lot of that location selected under no name filter and the default sort (`BulkSelection#restart!`'s `all:`; spec 059 decisions 1, 3, 4): it replaces any stored selection, reads no parameter but the location id in the path (another account's location or a removed one is 404), and answers 303 to `/collection?bulk=1&location=<id>`, where the bar reads "All 12 items selected" and "Move to…" works at once (spec 059 FR-1, AC-2.1–AC-2.4, AC-4.1–AC-4.3). A deck's refusal page does the same under the filter `deck:<location id>` ("<Deck> (all zones)"), through `POST /decks/:id/selection`, which finds the deck as `Decks::RemovalsController` does (another account's deck, a place's or a zone's id and a removed deck are 404) and shares the sequence with the place's shortcut in the `BulkModeShortcut` concern (spec 067 decisions 1–3, FR-1, AC-2.1–AC-2.4, AC-4.1–AC-4.3). In bulk mode, paging, sorting, filtering and the actions all submit one form with the page's ticks, so unsubmitted ticks are never lost without scripting (spec 006 FR-4). The selection:

- belongs to the session, tied to the name filter, location filter and sort it was made under (`bulk_selections.query`, `location_filter`, `sort_key`); a page under another of any shows nothing selected, and changing one clears it (spec 006 AC-5.6, FR-4; spec 037 decision 5, AC-5.3);
- is either a set of ticked lots, or every matching lot with exceptions, resolved against the account's lots and the filters when an action runs (spec 006 AC-5.4, AC-5.5, AC-7.8, FR-4);
- stores its location as the canonical string it was made under and applies it as a plain predicate on the account's lots, never re-resolved to all: a removed or foreign location selects nothing, a removed deck's `deck:<id>` included, so an action on it answers "None of the selected items are in your collection any more." (spec 037 decision 7, AC-5.5, AC-5.8; spec 065 decision 4, AC-6.7, AC-6.8). Pagers, sort headers, the actions and `Done` use the page's rendered filters (`rendered_q`, `rendered_location`); only Filter applies what the fields show, and keeps the page only when neither filter changed (spec 037 decision 5);
- counts copies: "0 of <matching> selected", "12 of 4,812 selected", "All 4,812 items selected" (spec 006 AC-5.1–AC-5.4);
- changes only through submissions; a header toggle resets to everything or nothing, then only rows that differ from their rendered baseline apply (spec 006 FR-4, AC-5.10);
- is cleared by `Done` (back to the saved view with the same filter and sort, the view preference unchanged), discarded when the session ends, and deleted by an import apply that writes a lot (spec 006 AC-4.5, FR-4; spec 028 decision 7).

An action with nothing selected is 422, "Select at least one item."; a selection whose lots are all gone or not the account's is 422, "None of the selected items are in your collection any more." (spec 006 FR-5, AC-8.1).

**Set condition** (its own page): the vocabulary's scale or "Not specified" (anything else is 422, "That isn't a known condition."); every selected lot gets it; lots that reach one identity merge (each keeps its place or zone, so they merge only within one: spec 062 AC-5.7b); all or nothing at the cap, with 422 "Nothing changed. <name> (<SET> · <number>) would have more than 9,999 copies in one lot." naming the first over-cap lot in the table's order; 303 back to the bulk table with the changed lots (a merged lot too) selected. "Set the condition of <n> items to <label>." or "Cleared the condition of <n> items." (spec 006 Story 6; spec 032 AC-7.3).

**Move to…** (its own page, shown only while the account has a place or a zone; `/collection/move/new`, `POST /collection/move`): "Move <n> items" with a required To select ("Choose…" submitting `""`, "No location" submitting `none`, then "Places" and "Decks" as on the forms, a zone's value being its location id, never a deck's own row; the filter's own place or zone is left out, "No location" is left out under the "No location" filter, and a deck filter leaves out nothing, since the selected lots sit in several zones) (spec 065 AC-3.1, decision 7). Every copy of each selected lot moves (`Lot::BulkMove`, which needed no change for zones): a lot that meets no lot of its identity in the destination stays the same lot, one that does merges into the destination's lot, selected lots of one identity become one (the first in the table's order survives), a selected lot already there stays and counts as "already there" (a lot in the destination zone included), and a lot in a zone moves out of it when the destination is another place, another zone or none, from every zone of a deck under "<Deck> (all zones)" too (spec 065 AC-3.2, AC-3.4); all or nothing at the cap. 303 to the bulk table with "Moved <n> items to <name>." ("…to Izzet Tempo › Main.", "…to no location."), plus "<m> items were already there." when any were. Under all locations the lots now holding the moved copies are selected; under any location filter, "No location", a place, a zone or a deck, the selection restarts empty, even when the lots still match it (`BulkSelection#after_move!`; spec 065 decision 12, AC-6.11). No Undo; it doesn't supersede the removal's. Refusals (422, move page, selection kept): "Choose where to move them." on To, "The selected items are already in <name>." (the label for a zone) / "…already have no location.", "Nothing moved. <name> (<SET> · <number>) would have more than 9,999 copies in one lot."; 404 for a destination that isn't a place or a zone of the account's, a deck's own row, another account's location and a removed one included (spec 065 AC-3.3, which supersedes spec 062 AC-5.2 and spec 041 AC-2.1's list of destinations); 303 "You have no locations yet." with no place and no zone. The order of answers: a GET with no selection, no location, no lot selected, no destination, a foreign destination, the move (spec 041 decisions 1–6, Stories 1–4, FR-1–FR-3).

**Remove** (a confirmation page, "Remove <n> items?") removes the selected lots and keeps one undo record for the session: 303 to the bulk table with the selection cleared and "Removed <n> items from your collection." with an Undo button, the only way to it (spec 006 AC-7.1–AC-7.3). The record:

| State | Moves on | Then |
|---|---|---|
| Undoable (holds each removed lot's printing, finish, condition, price paid, quantity and location) | Undo | The lots come back, each in its place or zone if the account still has it (a zone that went with a removed deck doesn't count), else unplaced; rows that then share an identity are one, merging into an existing lot; all or nothing at the cap ("Nothing restored. <name> (<SET> · <number>) would have more than 9,999 copies in one lot."). "Restored <n> items to your collection." plus "<n> lots came back without a location." when any did. 303 to the collection URL it carries if that is a collection path, else the collection (spec 006 AC-7.4, AC-7.5; spec 032 P5, AC-7.4, AC-7.5, AC-7.8) |
| Undoable | Any other removal in the same session (bulk, one lot, or a number-entry or scanner Undo that removes a lot) | Superseded |
| Used or superseded (a stub with no lot data) | Undo again | 422, "This removal can no longer be undone." |
| Any | The session ends | Discarded; an Undo then signs in and answers 404 (spec 006 AC-7.6, FR-6) |
| Undoable | An import apply that writes a lot | Superseded, in every session of the account (spec 028 decision 7) |

At most one undoable record per session, backed by a partial unique index (spec 006 FR-6). When only the restored rows themselves pass 9,999 and no held lot does, the cap message names the first such row (plan-level ruling O2, recorded in spec 032's `verification.md`).

### Number entry

`/collection/number_entry` needs a signed-in collector even when the catalog is open (spec 026 decision 1, AC-1.10). It is linked from the collection page's head, More, and the empty collection's sentence.

1. **Set and language.** The set field offers every set with an active entry of any kind, newest first, undated last, then by code, as "Name (CODE)"; it resolves typed text by code, exact name (any case) or the shown form, and otherwise says "No set matches “<text>”. Type a set code or choose a set from the list." The language defaults to EN if the set has it, else the language most of its active entries have (ties to the first code); with one language no field shows. The set's type, code and language are in the URL. With no catalog loaded the page says so and shows no form (spec 026 decisions 2, 9, AC-1.3–AC-1.11, Error Scenarios).
2. **A line** is number, quantity (1–9,999, default 1), finish and, while the account has a place or a zone, Location ("No location" first, then "Places" and "Decks" with each zone as "Deck › Zone", as on the forms; spec 065 AC-4.1, which supersedes spec 034 decision 1's "places only"). The finish defaults to the type's first in `finish_order` so typed and scanned copies share lots; finish and location carry over in the URL after an add. A page link whose `location` is no longer the account's shows "No location" and doesn't raise, and one whose `location` is a zone the account still has shows it chosen (spec 026 decision 3; spec 034 decisions 1, 2, AC-4.2; spec 065 AC-4.4).
3. **Matching** among the set and language's active entries: an exact match of the trimmed number first; only if none, ignoring case and leading zeros. Two or more ask the collector to choose; the choice (`pick`, the entry's external key) is checked on the server. None: "No card numbered <number> in <set name> (<LANGUAGE>)." (spec 026 decision 8, AC-2.6–AC-2.10, AC-4.1).
4. **Adding** is at once, through `NumberEntry.add!`: `Lot.add!` with the line's finish (none for an entry that lists no finishes) and location, and the line recorded in the same transaction, at most once per line key (`NumberEntry::KEY_FORMAT`). The notice reads "Added <n> × <name> (<SET> · <number>, <finish>) in <location> to your collection.", without the place for an unplaced line. A refused line comes back as typed: a bad quantity, finish or location (a deck's own row, another account's or a removed one: "That location isn't one of yours any more. Choose again.") on its field, a malformed line key on the form, and the cap ("One lot can hold at most 9,999 copies.") as a page alert (spec 026 decisions 4, 10, Story 4, FR-3; spec 034 decisions 3, 5, Story 4).

The list:

| State | Moves on | Then |
|---|---|---|
| No list | First add | The account's one list opens (unique per account) |
| A kept line | Undo, while its lot exists, is the account's and holds at least the line's quantity | The copies leave that lot as it now is (removed when none are left); the line leaves the list; "Undid <n> × <name>." Removing a lot this way supersedes the session's bulk Undo (spec 026 decision 5, AC-3.2, AC-3.3, AC-3.5) |
| A kept line | Its lot was removed, merged away or edited below the line's quantity | "Changed in your collection", no Undo; a request is 422 "Those copies have changed in your collection, so they can't be undone here." (spec 026 AC-3.4; spec 032 AC-7.6) |
| Any | Done | The list and its lines are deleted; the copies stay; back to the collection (spec 026 AC-3.7). An Undo of a line of a list Done cleared, or another account's line, is 404, "That line is no longer in your list." (spec 026 AC-3.8) |
| Any | An import apply that writes a lot | Destroyed, as Done would (spec 028 decision 7) |
| Any | The account is deleted | Deleted with it (spec 026 AC-3.9) |

The page shows "This list: <lines> lines, <copies> cards", the newest `NumberEntry::SHOWN` lines, and the rest behind "Show all N"; a line names the place its lot is in now, "Deck › Zone" for a zone, and a line's Undo keeps a lot in its zone (spec 026 AC-3.1; spec 034 decision 3, AC-3.3; spec 062 AC-5.4, AC-5.7). The page asks Turbo to refresh with `replace`, not morph, so focus moves after each add (spec 026 Supersedes, against ADR 0015).

### The card page and search

The card page shows "Owned <copies>" with "<printings> printings" across every printing of the card, then "Your copies": "<copies> in <lots> lots" and one row per lot of every printing (set · number, finish, condition, language, Location, quantity, price paid; ordered newest printing first, then by the stored finish, condition and price as text and numbers, unspecified first, then unplaced first and by location, a zone under its deck's name; a zone reads "Deck › Zone": spec 062 AC-5.4), each with "Edit copy", "Move copies" and "Remove"; with none, "You don't have this card yet." and "Add a copy" (spec 004 AC-8.4–AC-8.6; spec 032 AC-4.1, AC-4.2). Unlike the grid and table, its Location column shows even for an account with no location, every row reading "No location" (open for the maintainer, spec 032 `verification.md`). "Printings" lists the shown printing, then the other owned printings, then up to `Catalog::CardOverview::NEWEST` newest unowned ones, each with its owned quantity (spec 004 AC-8.7). A card page URL with the collection mark starts its breadcrumb at Collection and marks that section; the mark is kept on its links and after its adds, edits, moves and removals; the Referer is never used (spec 004 AC-8.9, FR-9). A visitor on an open catalog holds nothing and nothing about a collection is queried (spec 023 FR-3).

The card page's head has an **Add to deck** link, a secondary button with the decks icon before "Add a copy", for a signed-in collector on a printing a proxy can be made of: a retired printing, a token or an art card, or a printing whose collectible type has no vocabulary or no source, has none, and neither has the page, so "My copies" is not offered for it either (spec 071 decisions 1, 2). A visitor sees none of it (spec 023 FR-3, AC-4.1). It opens `GET /catalog/entries/:entry_external_key/deck_additions/new` (`DeckAdditionsController`, `Deck::Addition`; the markup is `AddToDeck`), which carries the collection mark and whose back link and Cancel return to the card page (spec 071 decision 2). "Deck and zone" is one select of the zones of the account's decks of the printing's collectible type, "Deck › Zone" under one group, Considering among them, no place and no "No location" (`Location::Choices#decks_of`; spec 071 decision 3). "What to use" is "My copies", when copies are free, and then one proxy option per finish the printing lists, or one with no finish for a printing that lists none; with one option it is chosen, with more nothing is (spec 071 decision 9, which supersedes spec 060 decision 14's single proxy option for a printing with several finishes). "My copies" counts the copies of the *card* in no deck zone, of every printing (`Lot::FreeCopies` over `Lot.free`), and says where they are, in the order a count takes them: "3 free: 2 in Blue binder, 1 in Red box", at most `PLACES_SHOWN` places and then "and 2 more places" (spec 071 decisions 4, 5, 7). A count takes the shown printing's free lots first, then the other printings' newest first, within a printing in "Your copies"' order, whole lots while one fits and the rest from the next, which splits (decision 5); the move is `Lot::MoveIntoZone`, all or nothing, in one write transaction that reads the free copies under the write lock, so the count is judged on what is free at the write (spec 071 FR-3; the shared pieces are spec 070's). "How many" is 1 up to the free total for My copies, 9,999 for a proxy, with no `max` in the markup because the limit follows the radio and the page works without scripting (decision 8). A proxy is recorded through `Deck::Proxy.add!` and no take changes one (decisions 4, 6). A refusal is a 422 re-render with what was typed and one sentence under its field, or above the actions for a lot that would pass the cap or can't be saved; a zone that is not one of the account's zones of a deck of the printing's type is a 404 (decision 11). Success is a 303 to the card page with the notice, "Moved 3 copies of Lightning Bolt to Izzet Tempo › Main." or spec 068's proxy sentence (decisions 10, 16, ruled by the maintainer). With no deck of the printing's type the page says so and links to New deck, with no form (decision 12). On a phone the head's three controls stay on one line: below 640px of the page container the `Add to deck` link drops its icon (`c-item__adddeck`) and the row's gap is 4px, because with both they need 318 to 326px against 297px at 360px; the deck page's head, which shares `c-item__actions`, is unchanged (spec 071 AC-1.5; `additions.css`).

Search and the printings page show each owned printing's quantity ("×3") on its tile, counted from the account's lots in a bounded number of queries (spec 004 FR-14); an unowned tile shows its image at full opacity with a "Not owned" tag on its own meta row, which ends the link's accessible name, and its add control sits at the foot of its cell so a row's add buttons are level (spec 004 AC-6.3, AC-6.6; spec 021 decisions 1–7). Search tiles show no place (spec 033 Non-Goals).

## Decisions not in an ADR

- **Lots merge on identity;** quick add specifies nothing, so repeated quick adds fill one lot (spec 004 Open Questions, AC-7.4, AC-7.5).
- **An edit that collides with another lot merges into it,** and the other lot survives (spec 004 AC-10.2; `Lot#revise!`).
- **Grid to look, table to manage:** the grid stays the default, the view is saved per user by any non-bulk URL that names one, and bulk mode always shows the table (spec 006 Goals, FR-1).
- **The selection is stored on the server per session,** not in the page; "every matching lot" is its own state (spec 006 FR-4).
- **Only the destructive bulk action has an Undo,** one per session, valid until the next removal or the session's end, with no time limit (spec 006 Open Questions, FR-5, FR-6).
- **Bulk actions answer with a redirect,** not Turbo Streams replacing rows, because both are submitted from their own pages (spec 006 FR-5).
- **The location is part of the lot's identity;** moving some copies splits a lot (maintainer, 2026-10-23; spec 032 decision 1; ADR 0025).
- **A location that holds copies can't be removed;** unplacing and merging on removal was not chosen (maintainer, 2026-10-23; spec 032 decision 3, superseding spec 029 decision 3's second half).
- **Move copies works on one lot, from the card page;** Move to… in bulk mode moves whole lots, with no Undo, and leaves a selected lot already there alone (maintainer, 2026-11-06; spec 041 decisions 1–3).
- **Bulk Move to… writes with `update_all` and `delete_all` on the account's lots, against the models rule, for the 2-second bar:** every statement is tenant-scoped and bound, the cap and identity collisions are checked first, `Lot`'s only callback is the `lot_key` builder (`before_validation`), which these writes reproduce (the SQL in `move_alone!`, `Lot.key_for` in `merge!`); it has no `dependent:` associations, and finish and condition aren't written, so `normalizes` isn't bypassed, and the foreign keys cascade or nullify what points at a lot (`Lot::ConditionChange#update_alone!` is the precedent; spec 041 FR-2, D1 of its plan).
- **A place is a name and nothing else** (no order or notes) (maintainer, 2026-10-20; spec 029 decision 4). A location as a whole now has a kind, and a zone has a parent: spec 062 supersedes decision 4's "no kind, no nesting" for locations, leaving places as they were (ADR 0028).
- **A deck and its zones are location rows, and zones are stored rows with their name copied from the registration when the deck is made** (maintainer D1, 2026-11-10; spec 062 decision 1; ADR 0028). A lot sits in a zone and never in a deck's own row; names are unique per parent, so every deck has a "Main". A release that renames a zone's display name leaves existing decks with the old text until a migration says otherwise: the key is the identity, the name a label (ADR 0028 Consequences).
- **The format is the extension's, the deck names its collectible type, and the New deck form's value is the pair `<type>/<key>`** so two collectibles that both register `standard` stay apart (maintainer D4; spec 062 decision 2, AC-1.8). MTG registers Casual (the default), Standard, Pioneer, Modern, Legacy, Vintage and Pauper (zones `main`, `sideboard`, `considering`) and Commander (`commander`, `main`, `considering`); a registration that is wrong stops boot (`Catalog::Formats.verify!`), and the contract is written in that module's comment, so a second collectible needs no change to the core (spec 062 FR-2).
- **Rename and Remove are ghost buttons on each Decks row, and the deck's name is a link to the deck page** (maintainer D5, option A; spec 062 decision 5, which differs from spec 060's `DecksIndex` preview in the row actions and no Proxy column; the name became a link with spec 066 decision 1).
- **A deck is removed only while empty,** refused as a place is, with a shortcut into bulk mode on its refusal page under the filter `deck:<id>` (`Decks::SelectionsController`; spec 062 decision 7, whose "no shortcut" clause spec 067 supersedes; spec 067 decisions 1, 2, [#302](https://github.com/plainprogrammer/Collector/issues/302)).
- **A lot in a zone is shown by one label, and every picker and the filter offer zones.** Spec 062 did the label and a read-only Edit copy early (maintainer D6; spec 062 decision 6); spec 065 (#252) replaced the read-only field with the grouped select, so Edit copy, Move copies, bulk Move to…, number entry, the sitting and the filter list zones as "Deck › Zone", the filter also "<Deck> (all zones)", and the tiles under a filter still show no place line (spec 065 decisions 1, 2, 6, 13; supersedes spec 062 decision 6's read-only field).
- **Locations are reached from the header and More, not a tab** (spec 029 decision 8).
- **No place line or Location column on the grid and table, and no Location field on the forms or number entry, while an account has no location** (spec 032 P3; spec 033 decision 2; spec 034 decision 2). The card page's column is the exception (below).
- **A tile names one place and counts the rest** ("+N more") rather than listing every place or splitting the tile (maintainer, 2026-10-26; spec 033 decision 1).
- **A row's place line wraps and a tile's is cut:** the phone line and the wide cell wrap (the cell at 20rem), a name with no space breaks inside itself, and the rule isn't scoped away from an account with no location (maintainer, 2026-10-27 and 2026-11-06; spec 048 decisions 1–4, which supersede spec 033 decision 5 and FR-5's truncation for rows).
- **The wide table's name column gives in a band just above the breakpoint, so the table is never wider than `.c-collection` for a short name from 640px of container up:** the other columns need about 531px, and a name cell that holds its whole name (every cell is `nowrap`, so its minimum is its maximum) pushed the table past its container by up to about 25px for containers of 640 to about 670px (669px measured for "Lightning Bolt"). For containers of 640 to 699px the name link (`.c-table__name a`, in a `@container collection (min-width: 640px) and (max-width: 699px)` rule in `additions.css`) is clamped to one line with an ellipsis; `white-space:normal` and `overflow-wrap:anywhere` on its `div` lower the column's minimum to a few characters without lowering its natural width. The clamp is on the link, not the `div`: focusing a link inside a clipped box scrolled the box and clipped the focus ring. From 700px up nothing changes: a `width`, `max-width` or `contain` on the cell would zero its natural width and narrow the column in wide layouts, and with the name shrinkable at any width auto layout shares a shortfall in proportion to how far each column can shrink, so beside a long place name (spec 048) the name was cut at 800 to 1024px where the wrapping Location cell is meant to give. Limits: a card name longer than about 170px (a bit more than 25 characters) still overflows a container from 700px up, as it did, and in the band a cut name has no other place to be read in full on a mouse (no `title`); in bulk mode the checkbox column fits too (measured at 735 to 800px frames). Below 640px the name stays whole (maintainer ruling on [#208](https://github.com/plainprogrammer/Collector/issues/208), 2026-11-09; `spec/system/collection_table_fit_spec.rb`; [TableItemLink](../design-system/components/TableItemLink.md)).
- **Number entry's finish defaults to the type's first and carries over;** each line adds at once; there is no live preview of the match (maintainer, 2026-10-15; spec 026 decisions 3, 4, 7). The Location field is on each line and carries over (spec 034 decision 1).
- **Number entry offers sets and matches entries of every kind,** tokens included (spec 026 decision 9).
- **An unowned search tile keeps its image unfaded and says "Not owned"** (maintainer, 2026-10-13; spec 021 decision 1), as a rule of the project's own in `additions.css`; `components.css` still carries the fade it overrides (spec 021 decision 8; spec 057 decision 12).
- **A count takes free lots in a stated order** (the shown printing first, then newer printings, then the card page's order); the alternatives, the lowest condition first and the collector's own pick of lots, were not chosen: the first needs a ranking of conditions the core doesn't own, the second is #257's page (spec 071 decision 5).
- **A proxy of a printing with several finishes is one option per finish** (spec 071 decision 9; supersedes spec 060 decision 14's single option for such printings).

**Accepted limits and open issues:**

- The card page's "Your copies" shows its Location column, every row "No location", for an account with no location; whether it should hide as the grid and table do is open for the maintainer (spec 032 `verification.md`, Implementation review).
- An unknown sort direction with a known column sorts that column ascending, not the default order spec 006 AC-3.7 names (`CollectionTable::Sort.parse`).
- No sort by location (spec 037 Non-Goals); a move's merged lots stay merged when moved back (spec 041 decision 1); no partial lots in bulk (decision 2).
- [#50](https://github.com/plainprogrammer/Collector/issues/50): no "Free to use" or "In decks" on the card page. [#49](https://github.com/plainprogrammer/Collector/issues/49) built the deck itself and [#252](https://github.com/plainprogrammer/Collector/issues/252) put copies into it: a copy reaches a zone from the lot form, Move copies, bulk Move to…, number entry and the scanner, and the filter finds a zone or a whole deck (spec 065). The deck page, proxies and Add to deck are built (#253, #254, #255); the shape panel (#256) is not; a deck's format changes in the app since spec 064 ([#251](https://github.com/plainprogrammer/Collector/issues/251)), and the "Free to use" and shape-panel rules for Considering are under "A deck" above (spec 062 Non-Goals, superseded by spec 064 for the format).
- The card page's `Add to deck` is hidden for a retired printing or a token, even for My copies (spec 071 decision 2).
- `Deck#zones` is ordered by id, which is the format's order only while every zone was written with the deck: a zone the import's repair adds later, and now a zone a change of format adds (Commander to Modern lists Sideboard after Considering), gets a later id, so it shows last there. The deck page orders what it reads by the format's registered order (spec 066 decision 3, `Deck::Page`), so it reads Main, Sideboard, Considering; `Deck#zones` itself is unchanged (spec 062 verification, open items; spec 064 "Supersedes and updates").
- `POST /collection/selection` accepts any location id as a stored filter (spec 037 decision 7), so any id can be stored, a deck's own among them, although no page offers one (a zone's and `deck:<id>` are values the filter offers since spec 065, a deck's own id is not); `spec/requests/bulk_zone_filter_spec.rb` pins that each bulk path then acts on the account's own lots in that zone, keeps a lot in its zone unless the collector moves it, and never unplaces one by accident (spec 062 decision 6).
- Collector numbers with symbols a keyboard lacks match only when typed exactly; such cards are added from their card page (spec 026 decision 8).
- Number entry can't tell apart one set code in two collectible types; the type travels in the URL with the code (spec 026 Non-Goals).
- A form opened before its location was removed answers 404 when submitted (spec 032 decision 6).
- Whether the "×N" badge on a card image counts as a stamp under Scryfall's image guidelines is not ruled on (spec 021 Open Questions). `ItemTile.md` points to `UnownedTile` for the marker (spec 021; spec 057 decision 12).
- Spec 034 was self-reviewed only; the maintainer's review is owed, and AC-3.2 (a moved or merged line) and AC-5.1 (the select in a browser) have no example of their own (spec 034 `verification.md`).
