## Open items

1. **A zone retired from a registration whose name a new zone then takes** would be skipped by the zone repair's insert (`ON CONFLICT DO NOTHING` on the zone name index), and a lot naming the new zone would raise inside the apply's transaction: it rolls back and the collector gets the error page. Out of scope: a release that does it needs a migration and an upgrade note (ADR 0028 Consequences). Recorded in `data-portability.md`.
2. **A deck that gains a missing zone through the repair gets it with a later id,** so `Deck#zones`, which orders by id, shows it last and not in the format's order. It matters to #253 (the deck page). Recorded in `collection-and-lots.md`.
3. **`POST /collection/selection` accepts any location id as a stored filter** (spec 037 decision 7), so a zone's or a deck's id can be stored although no page offers one. `spec/requests/bulk_zone_filter_spec.rb` checks that each bulk path is safe for a zone's and a deck's id (it acts on the account's own lots in that zone, keeps a lot in its zone unless the collector moves it, and never unplaces one by accident). Recorded in `collection-and-lots.md`.
