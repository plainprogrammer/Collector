# Research: Manage Locations

Findings the plan rests on, each read from the code or a gem's source, or shown by a read-only one-line probe of Ruby and `json_schemer` (nothing was written, migrated or run from the app; plans here are not executed before approval). The probes: the name pattern against `json_schemer` on 14 strings (words, double space, padding, tab, U+0085, U+2028, U+200B, U+3000, U+00A0, U+0007, empty, NFD, CJK); `downcase(:fold)`, `unicode_normalize(:nfc)` and `\p{White_Space}` on the strings of decision 5; the White_Space set Ruby reports, which equals the explicit list in the pattern (U+0009 to U+000D, U+0020, U+0085, U+00A0, U+1680, U+2000 to U+200A, U+2028, U+2029, U+202F, U+205F, U+3000).

1. **`json_schemer` 2.5.0's `ecma` resolver accepts `\p{…}` properties and explicit ranges.** `lib/json_schemer/ecma_regexp.rb` implements `UnicodeProperty::All` and `Escape::Unicode`, and passes the text of each token to Ruby unchanged, except anchors (`^` becomes `\A`, `$` becomes `\z`) and `\s`/`\S`, which it replaces with `[\t\r\n\f\v﻿ \p{Zs}]`. That `\s` **omits U+0085 and U+2028** (both Unicode White_Space), so the name pattern must not use `\s`. It spells the sets out: `\p{Cc}`, `\p{Cf}` and an explicit White_Space list.
2. **A pattern that fails one way gives one schema error.** A name of `""` would fail both `minLength` and a `+` pattern, giving two problems at one pointer; the examples' `problems.json` names exactly one. So the pattern lets the empty string through (`^(word( word)*)?$`) and `minLength: 1` is the one that fails it; a lone space fails the pattern only.
3. **Ruby does the Unicode work in core:** `String#unicode_normalize(:nfc)` (raises `ArgumentError` on invalid byte sequences, so the normalising function returns invalid input unchanged and the model refuses it), `String#downcase(:fold)` (full case folding: "Straße" and "STRASSE" fold to "strasse"), `\p{White_Space}`, `\p{Cc}`, `\p{Cf}`. `String#length` counts code points.
4. **SQLite's `length()` on text counts characters (code points)**, so a check constraint `length(name) BETWEEN 1 AND 60` is the same measure as the model's. Its default binary collation compares UTF-8 bytes, which is code-point order, so `ORDER BY name_key, name` is decision 2's order with no collation.
5. **Rails 8's SQLite adapter begins write transactions `IMMEDIATE`,** and `save` runs validations inside the transaction, so a cap check (`count < 500`) in a validation and the insert are one atomic step per writer (AC-1.13). The two-writer race is by hand in `verification.md`, as spec 028 did for AC-2.3; a deterministic spec covers the cap sequentially and the unique index through `save(validate: false)`.
6. **Spec 028 as merged is the base:** see "Spec 028 references" in `plan.md` for what each citation of 028 now is.
7. **`Lot.upsert_all` is the precedent for bulk writes** (028 FR-3). Locations use one `delete_all` batch and one `Location.upsert_all` (`unique_by: %i[account_id name_key]`, `update_only: %i[name updated_at]`), so a renamed location keeps its id and an added one is inserted, in two statements whatever the number of locations (NFR "bounded number of statements").
