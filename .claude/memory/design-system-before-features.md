When a feature changes what the app looks like or how it behaves, settle and file the design-system issues (rules, components, previews) first, chosen from mock-ups the maintainer reviewed, before any feature issue starts.

**Why:** the maintainer asked that "the design system is clear and our design goals are well-defined before other development starts" (decks scoping, 2026-11-09).

**How to apply:** when scoping a theme, find the design-system changes up front, mock the options in the brainstorm visual companion with the real CSS ([[brainstorm-mockups-with-collector-css]]), and make those issues the first dependencies. See [[design-system-owned-in-code]].
